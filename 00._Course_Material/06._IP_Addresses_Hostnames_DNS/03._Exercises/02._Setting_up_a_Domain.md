## Introduction

In this exercise, you will buy a domain name from a domain registrar and set up DNS records that point it to a web server.

You can use any registrar, such as simply.com, one.com, namecheap.com or porkbun.com. Using one.com is optional, just as Azure is optional for VMs, but there is a voucher code for a free one.com domain in Teams.

> [!WARNING]
> **Cancel the domain subscription once your Mandatory II has been approved.** The domain renews automatically after the exams, and the renewal is not free. You will get a warning before it renews and a grace period to react but it's easier to just cancel the subscription ahead of time.

# Verify the A records

Run the commands below from your local machine. Replace `<yourdomain>` with your full domain, including the TLD (e.g. `ekcloud.dk`).

## 1. Check one.com's nameserver

This asks one.com directly, so it works as soon as the records are saved:

```bash
$ dig @ns01.one.com A <yourdomain> +short
$ dig @ns01.one.com A www.<yourdomain> +short
```

Both should return your server's IP. If not, recheck the records in the one.com DNS settings.

## 2. Check public DNS

**`.dk` domains only:** newly registered `.dk` domains must be verified with MitID before they appear in public DNS. Look for an email from **Punktum dk** and complete the verification first.

```bash
$ dig A <yourdomain> +short
$ dig A www.<yourdomain> +short
```

Both should return your server's IP before you continue to the next tutorial. If they come back empty, the records haven't propagated yet. This usually takes a few minutes but can take longer, so wait and try again.

## [Optional] Setting up HTTPS

If you want to learn how to set up HTTPS for your domain, then follow the instructions below.

### Set up TLS certificate with Let's Encrypt (Certbot)

[Let's Encrypt](https://letsencrypt.org/) is a free, automated and open certificate authority (CA) that issues TLS certificates. [Certbot](https://certbot.eff.org/) is the tool that requests a certificate from Let's Encrypt and saves it on your VM. A TLS certificate is needed to make your website accessible via HTTPS.

SSH into the VM and run the following commands:

```bash
sudo docker ps
sudo docker stop $(sudo docker ps -q --filter "publish=80")
sudo docker run --rm -it -p 80:80 -v /etc/letsencrypt:/etc/letsencrypt certbot/certbot certonly --standalone -d <yourdomain.dk> -d www.<yourdomain.dk>
sudo ls /etc/letsencrypt/live/<yourdomain.dk>/   # confirm that the certificate files are present: fullchain.pem + privkey.pem
```

The web server is stopped first because Certbot needs port 80 for itself: Let's Encrypt verifies that you control the domain by connecting to it on port 80. The web server is started again in the "Rerun Nginx with TLS" step below.
Certbot will ask for an email (for renewal warnings) and agreement to the Terms of Service. On success, your cert lands in /etc/letsencrypt/live/<yourdomain.dk>/.

You only need to do this once. Subsequent deploys reuse the existing cert.

## Open port 443 in the VM's firewall

Open port 443 in the VM's firewall. In Azure this is done under Network settings.

## Rerun Nginx with TLS

Create a config file for Nginx that enables TLS and redirects HTTP to HTTPS. Replace all 6 instances of  `<yourdomain.dk>` with your domain name:

```bash
mkdir -p ~/nginx
cat > ~/nginx/default.conf <<'EOF'
server {
    listen 80;
    server_name <yourdomain.dk> www.<yourdomain.dk>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name <yourdomain.dk> www.<yourdomain.dk>;

    ssl_certificate     /etc/letsencrypt/live/<yourdomain.dk>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<yourdomain.dk>/privkey.pem;

    location / {
        root  /usr/share/nginx/html;
        index index.html;
    }
}
EOF
```

Rerun Nginx with the new config and TLS certs:

```bash
sudo docker rm -f my-web-server
sudo docker run -d -p 80:80 -p 443:443 --name my-web-server -v ~/nginx/default.conf:/etc/nginx/conf.d/default.conf:ro -v /etc/letsencrypt:/etc/letsencrypt:ro nginx
sudo docker logs my-web-server
```

In the logs, you should see that worker processes have been started. 

Go to the browser and check. HTTPS should work now.
