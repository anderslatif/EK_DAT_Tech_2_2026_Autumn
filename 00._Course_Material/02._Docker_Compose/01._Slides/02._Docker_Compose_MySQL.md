# Get started

Create the file `compose.yaml` with the following content:

```yaml
services:
  db:
    image: mysql:latest
    container_name: my-mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: root
      MYSQL_DATABASE: mydb
      MYSQL_USER: user
      MYSQL_PASSWORD: secret
    ports:
      - "127.0.0.1:3307:3306"
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

# Additional explanations - I

**Port mapping**: It is common to expose the MySQL service in Docker compose to port `3307` rather than the the default to avoid conflict with any MySQL service running on the host machine.

**Volume**: The volume `db_data` is used to persist the `/var/lib/mysql` directory, which is the default location where MySQL stores its data.

**Environment variables**: Environment variables prefixed with `MYSQL_` are used to configure the MySQL service. They are only read the first time the container is started. Changing configurations requires deleting the container and volume first.

---

# Additional explanations - II

**Restart policy**: 

`restart: always` means that the container will be restarted automatically if it stops. This is useful for ensuring that the MySQL service is always available. If the container stops due to a crash / system reboot, it will be restarted automatically when Docker starts.

An alternative would be `restart: unless-stopped` which means that the container will be restarted unless it is explicitly stopped by the user. This is useful for ensuring that the MySQL service is always available, but allows you to stop the container if needed.

# Starting and stopping the service

Make sure that you are in the same directory as the file named exactly: `compose.yaml`.

Run the database in the foreground:

```bash
docker compose up
```

Use `CTRL + C` to stop the database.

Run the database in the background (`-d` = detached mode):

```bash
docker compose up -d
```

Use the following command to take down the service:

```bash
docker compose down
```

# Avoid leaking credentials with `.env` files

**1.** Create a file named `.env` in the same directory as `compose.yaml` with the following content:

  ```env
  MYSQL_ROOT_PASSWORD=root
  MYSQL_DATABASE=mydb
  MYSQL_USER=user
  MYSQL_PASSWORD=secret
  ```

**2.** Ensure that `.env` will not be commited by defining it in your `.gitignore` file.

`.env` is a standard name for the environment variable files and is commonly included in `.gitignore` templates.

---

# Getting environment variables from `.env`

**3.** Update the `compose.yaml` file to use the environment variables from the `.env` file:

```yaml
services:
  db:
    image: mysql:latest
    container_name: my-mysql
    restart: always
    env_file:
      - .env
    ports:
      - "127.0.0.1:3307:3306"
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

This block tells it to read the environment variables from the `.env` file and pass them to the container:

```yaml
    env_file:
      - .env
```

# Create a `.env.example` file

A common thing to help other programmers and yourself in the future is to create a sample file.

`.env.example` will be pushed and should not contain any secrets. 

Anyone cloning the repository knows that they should copy it to `.env` and fill in the values.

In `.env.example` add the required keys without values:

