# Adding a multi-stage build

In the exercise you updated your `Dockerfile` to this:

```Dockerfile
FROM maven:3.9.9-eclipse-temurin-21 AS build

WORKDIR /app
COPY pom.xml .
COPY src ./src
RUN mvn clean package -DskipTests

FROM eclipse-temurin:21-jdk-alpine
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar

ENTRYPOINT ["java", "-jar", "target/helloworld-0.0.1-SNAPSHOT.jar"]
```

It splits up the process into two stages: A build stage and a runtime stage. The `AS build` addition creates an alias for the first stage, so we can refer to it.

First stage will build the Spring Boot application as a `jar` file using the large Maven image (500 - 800 MB).

For the second stage, only the resulting `jar` will be copied into a smaller JDK image without the dependency cache, source code. Much smaller final image.

# Docker Compose with Spring Boot

Create a `compose.yaml` file in the root of your Spring Boot project with the following content:

```yaml
services:
  app:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "127.0.0.1:8080:8080"
    environment:
      SPRING_PROFILES_ACTIVE: docker
```

---

# Quick quiz

1. What is the name of the service?

  <details> 
    <summary>Answer</summary>
    app.
  </details>

2. What is the name of the expected Dockerfile and in which directory should it be located?

  <details> 
    <summary>Answer</summary>
    The expected Dockerfile is named `Dockerfile` and it should be located in the same directory as the `compose.yaml` file hence the `.`.
  </details>

3. From which port can you access the service on your host machine? And what is the internal container port?

  <details> 
    <summary>Answer</summary>
    The answer to both is `8080`: <host_port>:<container_port>.
  </details>

# Additional explanations

**Auto-generated container name**: Compared to the previous `compose.yaml` file, a `container_name` is not specified and a random container name will be generated instead.

**Image vs. build**: Compared to the previous file where the `image` key defined an image to pull from Docker Hub, the build section here tells Docker Compose to build an image using the provided `Dockerfile`.

**Spring profiles**: The `docker` profile makes Spring Boot load `application-docker.properties` (from `src/main/resources`) on top of `application.properties`, overriding hostnames and ports for Docker. Then `localhost` becomes `db` -> `spring.datasource.url=jdbc:mysql://db:3306/helloworld`.

# Solution - Combined MySQL and Spring Boot compose file

Update the `compose.yaml` file:

```yaml
services:
  db:
    image: mysql:latest
    container_name: my-mysql
    restart: always
    env_file:
      - .env
    ports:
      - "127.0.0.1:3307:3306"
    volumes:
      - db_data:/var/lib/mysql
  app:
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "127.0.0.1:8080:8080"
    env_file:
      - .env
    environment:
      SPRING_PROFILES_ACTIVE: docker

volumes:
  db_data:
```
