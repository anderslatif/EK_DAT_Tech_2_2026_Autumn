# Deploy Bashcrawl to GHCR

Refresh your knowledge of how to build an image to GitHub Container Registry (GHCR) and push it to GHCR by doing it from scratch with the Bashcrawl project.

---

## Setup

Fork [this repository](https://github.com/anderslatif/bashcrawl). The bashcrawler files are in the `entrance` folder. 

## Create a Dockerfile

Create the file `Dockerfile` in the root of the repository with the following content:

```Dockerfile
FROM alpine:latest

RUN apk add --no-cache bash

COPY entrance /bashcrawl/entrance

WORKDIR /bashcrawl/entrance

ENTRYPOINT ["/bin/bash"]
```

It creates a Docker image based on the latest Alpine Linux image and installs bash.

It then copies the `entrance` folder from the repository into the image and sets the working directory to `/bashcrawl/entrance`. 

Finally, it sets the entrypoint to run bash when the container starts.

---

## Run the Docker image locally

Test it out with:

```bash
docker build --tag bashcrawl:latest .
docker run -it bashcrawl:latest
```

You should see a prompt placing you at the entrance of the game.

# Create a GitHub Actions workflow file that deploys the image to GHCR

Create the file `.github/workflows/cd.yaml` with the following content:

```yaml
name: Continuous Deployment
on:
  push:
    branches:
      - main
env:
  REGISTRY: ghcr.io
  IMAGE_NAME: ${{ github.repository }}

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - name: Checkout
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1  # v7.0.1  2026-07-17
      - name: Log in to Container Registry
        uses: docker/login-action@dbcb813823bdd20940b903addbd779551569679f  # v4.6.0  2026-07-29
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}
      - name: Extract metadata
        id: meta
        uses: docker/metadata-action@v5
        with:
          images: ${{ env.REGISTRY }}/${{ env.IMAGE_NAME }}
          tags: |
            type=ref,event=branch
            type=sha,prefix={{branch}}-
            type=raw,value=latest,enable={{is_default_branch}}
      - name: Build and push Docker image
        uses: docker/build-push-action@53b7df96c91f9c12dcc8a07bcb9ccacbed38856a  # v7.3.0  2026-07-01
        with:
          context: .
          push: true
          tags: ${{ steps.meta.outputs.tags }}
          labels: ${{ steps.meta.outputs.labels }}
```

* The `env` section sets some variables that later steps can use (see `env.REGISTRY` and `env.IMAGE_NAME`). This is convenient for making the workflow more readable and maintainable.

* Permission are necessary to deploy to GHCR as the workflow needs to read the repository contents and write to the container registry.

* `docker/login-action` logs into GHCR using GitHub’s built-in token. If you want to log in to another Container Registry, you need to use Secrets for the password.

* `docker-metadata-action` generates Docker tags based on the branch name and commit hash. The metadata action automatically generates multiple tags:
  - `latest` - only for the main branch
  - `main-abc123` - branch name plus commit hash
  - `main` - branch name

* Finally, `docker/build-push-action` builds the Docker image and pushes it to GHCR with the generated tags and labels.

Feel free to change the hashpins.

## Test it out

Get the image from GHCR (replace `username` and `repository_name` with your values):

```bash
docker pull ghcr.io/<username>/<repository_name>:latest
docker run -it ghcr.io/<username>/<repository_name>:latest
```

You can also find these under the "Packages" section on the right side of your GitHub repository.
