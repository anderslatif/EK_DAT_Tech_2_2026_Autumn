# Become a new user

Create a new user, *alice*:

```bash
useradd -m -s /bin/bash alice
```

`-m` = creates a home directory

`-s` = sets the shell (Default is `/bin/sh`, not bash)

Create and add her to the a group called *students*:

```bash
groupadd students
usermod -aG students alice
```

Switch to a session as the *alice* user:

```bash
su - alice
```

`su` = switch user

`-` = start a login shell (load the user's environment)

# Check Ownership

Change directory to Alice's home folder.

First create a file called `test.txt`:

```bash
touch test.txt
```

List the file with the -l option to see the permissions and ownership:

```bash
ls -l test.txt
```

*Which user owns the file?*

*Which group owns the file?*

---

# Check Ownership - Explanation

1. The first `alice` column is the owner of the file 

2. The second `alice` column is the group that owns the file. 

That's because primary group is `alice` besides being a member of the `students` group as well.

Different permissions can be set for owners and groups.

---

# Check File Permissions

Notice that there are **3** sets of permissions for the file:

```bash
-rw-rw-r-- 1 alice alice 0 Jul 28 14:43 test.txt
```

It follows this pattern: `<owner><group><others>`


Each set of permission follow this pattern: `<read><write><execute>`

`r` = read permission

`w` = write permission

`x` = execute permission

**Quiz**: Go over the 3 sets of permissions. What are they allowed to do with the file? What aren't they allowed to do?

---

# File Permissions - Quiz Answers


1. `rw-` = permissions for the owner (Alice) of the file.

  Can read and write. Can't execute.

2. `rw-` = permissions for the group (Alice group) of the file.

  Can read and write. Can't execute.

3. `r--` = permissions for everyone else.

  Can only read. Can't write or execute.

*Can the alice user write to the file?*

*Who can execute the file?*

*What can the alice group do with the file?*

*How many can read the file?*

*Who can't write to the file?*

*Can students write to the file or not?*

# Change Ownership

Answer for the last question: No, students cannot write to the file since they are not in the `alice` group and therefore part of everyone else.

Let's allow all students to write to the file by changing the ownership:

```bash
chown alice:students test.txt
```

`chown` = change ownership

`<user>:<group>` = new owner and group

*What permissions do students have now?*

# First character in the permissions string indicates the type of file

Create a new directory and list it with the file:

```bash
mkdir test
ls -l
```

Result:

```plaintext
total 0
drwxrwxr-x 1 alice alice    0 Sep 15 13:07 test
-rw-rw-r-- 1 alice students 0 Sep 15 12:49 test.txt
```

As you can see, the first character indicates:

`-` = regular file

`d` = directory

# Overview - Permissions and their decimal representation


| Binary | Decimal | Permission |
|--------|---------|------------|
| 000    | 0       | ---        |
| 001    | 1       | --x        |
| 010    | 2       | -w-        |
| 011    | 3       | -wx        |
| 100    | 4       | r--        |
| 101    | 5       | r-x        |
| 110    | 6       | rw-        |
| 111    | 7       | rwx        |

# Change Permission (`chmod` = change mode)

You will need to use the decimal representation of the permissions to change them:

```bash
chmod <number><number><number> test.txt
```

The first number will apply to the user, then group, then others.

# Let's create a shell script

```bash
vim myscript.sh
```

The `.sh` extension is not necessary for it to become a shell script. Instead, we can add a line at the top called a [shebang](https://en.wikipedia.org/wiki/Shebang_%28Unix%29) that indicates what interpreter to run it.

```plaintext
#!/bin/bash

```

Try to run it:

```bash
./myscript.sh
```

We do not have permission:

```plaintext
-bash: ./script.sh: Permission denied
```

# File Permissions - Shorthands

We need to set file permissions. Luckily, there are shorthands as well.

The most common one is to give everyone execution rights to a file:

```bash
chmod +x test.txt
```

Be careful about doing this on servers as it is dangerously permissive.

Check out [this cheatsheet](https://linuxize.com/cheatsheet/chmod/) for more.
