# Running and Killing Processes

In this exercise, you will start processes, inspect them, and stop them using signals. You will also kill the shell you are logged in with and see what happens.

> **Why Docker?** Everyone in the class needs the *same* Linux. Git Bash on Windows only pretends to be Linux: it has no `pgrep`, no `pkill`, no `top`, and its `ps` shows different columns than the real thing. Inside a container you all get identical output, on Windows, macOS, and Linux alike.

## Step 1: Start a Linux Container

1. Make a new directory and move into it:
	```bash
	mkdir process-demo
	cd process-demo
	```
2. Create a file named `compose.yaml`:
	```yaml
	services:
	  linux:
	    image: almalinux:9
	    tty: true
	```
	We use AlmaLinux because that is the distribution you will meet on your Azure VM next week.
3. Start it:
	```bash
	docker compose up -d
	```
4. Open a shell inside the container:
	```bash
	docker compose exec linux bash
	```
	Every command from here on is typed **inside the container**, unless it says otherwise.

## Step 2: Install the Tools You Need

1. The AlmaLinux base image is minimal, so install the process tools:
	```bash
	dnf install -y procps-ng psmisc nano
	```
	`procps-ng` gives you `ps`, `top`, `pgrep`, and `pkill`. `psmisc` gives you `killall`.

## Step 3: Look at the Processes That Already Exist

1. List the processes in this container:
	```bash
	ps aux
	```
	Every line is a running process. The second column is the **PID**, the process ID.
2. Notice that one process has PID 1. Find out which one:
	```bash
	ps -p 1
	```

	> **Question:** On a normal Linux machine PID 1 is `systemd`, the init system that starts everything else. What is PID 1 here, and why is it different? Keep this in mind for Step 8.

## Step 4: Start a Process in the Background

1. Start a process that simply waits for 300 seconds:
	```bash
	sleep 300 &
	```
	The `&` puts it in the background, so you get your prompt back immediately. Bash prints something like `[1] 42` — `[1]` is the **job number** and `42` is the PID.
2. List the background jobs of your current shell:
	```bash
	jobs
	```
3. Find the same process with `ps`:
	```bash
	ps aux | grep sleep
	```
4. There is a shorter way to find a PID by name:
	```bash
	pgrep sleep
	```

## Step 5: Foreground, Background, and Suspending

1. Bring the sleeping job back to the foreground:
	```bash
	fg %1
	```
	Your prompt is now gone, because `sleep` is occupying the terminal.
2. Press `CTRL+Z`. This **suspends** the process — it is paused, not dead. Bash tells you it is `Stopped`.
3. Confirm it is stopped:
	```bash
	jobs
	```
4. Let it continue running, but in the background:
	```bash
	bg %1
	```
5. Check that it is running again:
	```bash
	jobs
	```

	> `CTRL+Z` sends the `SIGTSTP` signal, and `bg` sends `SIGCONT`. You have already been sending signals without knowing it.

## Step 6: Killing a Process

1. Start three sleepers so you have something to aim at:
	```bash
	sleep 300 &
	sleep 300 &
	sleep 300 &
	```
2. Kill one of them by job number:
	```bash
	kill %1
	```
3. Kill one by PID. First find the PID, then use it:
	```bash
	pgrep sleep
	kill <PID>
	```
	Replace `<PID>` with a number from the previous command.
4. Kill every remaining process with that name at once:
	```bash
	pkill sleep
	```
5. Verify that they are all gone:
	```bash
	pgrep sleep
	```
	No output means no matching process. `pgrep` also exits with status `1`, which you can see with `echo $?`.

## Step 7: Kill Signals

Plain `kill` does not mean "destroy". It means "send a signal". The default signal is `SIGTERM` (number 15), which politely asks the process to shut down. A program is allowed to catch that signal and clean up first — or to ignore it entirely.

1. See the list of available signals:
	```bash
	kill -l
	```
2. Write a small script that refuses to die politely. Create `stubborn.sh` with `nano`:
	```bash
	nano stubborn.sh
	```
	Put this inside:
	```bash
	#!/bin/bash
	trap 'echo "Caught SIGTERM, but I am not leaving!"' SIGTERM
	echo "I am stubborn, my PID is $$"
	while true; do
	    sleep 1
	done
	```
	`trap` registers a handler for a signal. `$$` is the PID of the running script.
3. Make it executable and start it in the background (`&`):
	```bash
	chmod +x stubborn.sh
	./stubborn.sh &
	```
	The script prints its PID on top of your prompt, so the prompt looks like it disappeared. Press `Enter` to get it back.
4. Find the PID of the script:
	```bash
	pgrep -f stubborn.sh
	```
5. Send it the default `SIGTERM` and watch it refuse:
	```bash
	kill <PID>
	```
	Replace `<PID>` with the number from the previous command. The script prints its message and keeps running. Confirm with `pgrep -f stubborn.sh`.

	It will say `Caught SIGTERM, but I am not leaving!`. Hit "Enter" to get your prompt back.

6. Now send `SIGKILL` (number 9), which the kernel handles directly. It cannot be caught, blocked, or ignored:
	```bash
	kill -9 <PID>
	```
7. Confirm it is really gone:
	```bash
	pgrep -f stubborn.sh
	```

	> **Rule of thumb:** always try `kill` first and reach for `kill -9` only when a process will not respond. `SIGKILL` gives the program no chance to save files, flush data, or release locks.

## Step 8: Kill the Shell You Are Logged In With

Now the interesting part. Your own shell is just another process.

1. Find the PID of your current shell:
	```bash
	echo $$
	```
2. Kill it:
	```bash
	kill -9 $$
	```

	> **What happened?** Your shell process died, so `docker compose exec` had nothing left to talk to and you were dropped back to your own machine's terminal. The container itself is still running, because the shell you killed was *not* PID 1 — it was an extra process that `exec` started alongside it.

3. Prove the container survived:
	```bash
	docker compose ps
	```

## Step 9: Watching Processes Live

1. Start the container again and go back inside:
	```bash
	docker compose up -d
	docker compose exec linux bash
	```
2. Install the process tools again:
	```bash
	dnf install -y procps-ng psmisc nano
	```
3. Watch processes update in real time:
	```bash
	top
	```
	Press `q` to quit.
4. Start a process that actually uses the CPU, and watch it in `top`:
	```bash
	yes > /dev/null &
	top
	```
	`yes` prints "y" forever as fast as it can. You should see it near the top of the list at close to 100% CPU.
5. Quit `top` with `q` and stop the process:
	```bash
	pkill yes
	```
	Use `top` again to confirm that it is gone.

## Step 10: Clean Up

1. Leave the container:
	```bash
	exit
	```
2. Stop and remove it:
	```bash
	docker compose down
	```

## Summary of Commands

| Command | What it does |
|---|---|
| `ps aux` | List all processes |
| `pgrep <name>` | Find PIDs by process name |
| `top` | Watch processes live |
| `<command> &` | Run a command in the background |
| `jobs` | List background jobs of this shell |
| `fg %1` / `bg %1` | Move job 1 to the foreground / background |
| `CTRL+C` | Send `SIGINT` — interrupt the foreground process |
| `CTRL+Z` | Send `SIGTSTP` — suspend the foreground process |
| `kill <PID>` | Send `SIGTERM` — ask a process to stop |
| `kill -9 <PID>` | Send `SIGKILL` — force a process to stop |
| `pkill <name>` | Kill processes by name |
| `killall <name>` | Kill all processes with an exact name |
| `echo $$` | Print the PID of your current shell |
